## 一、项目概述与架构

- 创建一个类似朋友圈的 Web 应用，用户可以发送图片、视频、文字动态，其他人可以查看和评论。
- 前后端不分离部署，不需要跨域配置。
- 后端使用 FastAPI，前端使用 React，FastAPI 直接托管前端静态文件。
- 前端状态管理使用 [Zustand](https://zustand.docs.pmnd.rs/)。
- 前端采用 [animal-island-ui](https://github.com/guokaigdg/animal-island-ui) 组件库，遵循其设计规范。
- 项目启动使用 bash 脚本，同时启动前后端，Ctrl+C 停止全部进程。
- 需要提供一个一键编译的脚本。
- 项目后续会被打包为 Docker。
- CPU 密集型耗时操作使用 FastAPI 的 [BackgroundTasks](https://fastapi.tiangolo.com/zh/tutorial/background-tasks/#dependency-injection) 进行。

## 二、数据库与存储

- 数据库采用 SQLite，使用 ORM 做兼容，便于切换数据库（暂不处理 SQLite 并发写锁问题，后期切 PostgreSQL 解决）。
- 使用 Alembic 管理数据库版本。
- 图片、视频等文件存储到固定文件夹，按「年-月」的目录结构组织。
- 数据库不存储源文件，只存储文件相对路径、文件名、大小、格式等元数据。
- 上传的图片、视频自动重命名为 `时间戳 + 6位随机UUID`，增加重复文件名检查，避免极小概率重复。
- 上传时自动生成缩略图（视频使用 ffmpeg 取首帧），缩略图采用 WebP 格式，支持渐进式加载。
- 信息流加载缩略图，点击查看大图。
- 缩略图规格：400px、80% 质量；大图规格：2160px、90% 质量；提供“查看原图”直接访问原始画质。
- 兼容主流的图片、视频格式，上传时自动重命名。
- 系统停止使用某个图片时（如更换头像、删除朋友圈），后端文件不删除，保留。
- 数据库添加合适的索引。

## 三、用户与认证

- 用户 Token 有效期 7 天，使用 Cookie 存储，自动刷新，长期不使用则自动过期。
- Cookie 存储 JWT 时需防 CSRF 攻击：设置 SameSite=Strict/Lax 或使用 Double Submit Cookie。
- JWT Secret 从环境变量读取，初次启动时如不存在则自动生成。
- 初次启动时若没有 `.env` 文件，自动从 `.env.example` 复制。
- 用户注册需填写邮箱（暂无邮箱验证，后期会加）。
- 采用邀请注册机制，每个用户可以生成、失效、续期邀请码（同一时间每人仅一个有效邀请码），邀请有过期时间，可自行选择，生成邀请链接（对外链接由环境变量定义）。
- 系统首次打开时有初始化页面，此时注册的账号为系统管理员（名称可自定义，role 为 admin）。
- 用户可以修改头像、昵称、签名、密码；忘记密码重置只能联系管理员。
- 新注册账号使用默认头像（后端存储的 PNG 文件），头像存储规则与朋友圈图片分开：`用户ID + 时间戳 + 随机4位UUID`，存储在单独的头像文件夹。
- 账号注销实现为将账号状态设置为注销（非数据库删除），前端显示用户名为“已注销”，头像为默认头像，但已发表的评论保留且不影响原展示。

## 四、功能需求

### 4.1 朋友圈与动态

- 支持发送、删除朋友圈动态（文字+图片/视频）。
- 动态可见范围设置：公开 / 仅好友。

### 4.2 评论与交互

- 支持链式评论，即可以指定回复某一条评论。
- 支持发送和删除评论。
- 需要点赞功能。
- 评论区支持发送图片。
- 用户点击他人头像/昵称，能进入他人主页，看到这个人的朋友圈；

### 4.3 好友关系

- 存在好友关系结构，目前不开发聊天系统。
- 好友关系为双向确认。
- 添加好友通过精确搜索邮箱实现。
- 非好友不可相互查看评论：如 A 发“仅好友”动态，B 是 A 的好友并评论，C 是 A 的好友但不是 B 的好友，C 不能看到 B 的评论。

### 4.4 管理功能

- admin 用户有独立管理界面：可查看统计信息、管理邀请码、管理内容、管理用户信息、停用用户、管理用户邀请码权限等。

### 4.5 健康检查

- 提供 `/api/health` 端点，用于监控和负载均衡器探测。

## 五、API 设计

- API 版本控制，使用 `/api/v1` 前缀。
- 信息流和评论列表必须分页（cursor-based 或 offset-based），避免数据量大时性能崩溃。
- 文件下载/访问接口要防止路径穿越攻击（如 `../../etc/passwd`），并进行鉴权，避免“仅好友可见”动态中的媒体文件被直接 URL 访问。
- 统一错误处理，错误响应格式标准化。

## 六、前端规范

- 前端使用 React + TypeScript。
- 前端静态文件由 FastAPI 托管，开启 gzip/brotli 压缩，build 时自动生成压缩文件。
- XSS 防护：用户发布的文字、评论内容渲染时做转义，防止注入恶意脚本。
- 前端代码检查：使用 ESLint + Prettier，结合 Git Hooks 实现提交前自动检查与格式化。
- 使用 Vite 构建。
- 使用响应式布局，同时适配桌面端和移动端。
- animal-island-ui 组件库缺少的内容，使用 Radix UI Primitives 做无样式组件 + 自定义样式。
- 对于组件库，使用 CDN 加载，jsDelivr 镜像：
```html
<!-- CSS 样式 -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/animal-island-ui/style.css">

<!-- JS（UMD/IIFE 格式，取决于包是否提供） -->
<script src="https://cdn.jsdelivr.net/npm/animal-island-ui"></script>
```

## 八、安全要求

### 8.1 文件上传安全

- 必须校验文件真实格式（不能只看后缀），禁止上传可执行文件。
- 限制单文件大小：图片 40M，视频 200M。

### 8.2 文件下载安全

- 防止路径穿越攻击；需要鉴权，防止越权访问媒体文件。

### 8.3 认证与鉴权

- 登录、文件上传等接口必须鉴权，防止越权操作。
- 密码要求至少 8 位，含有数字、字母、符号中至少两类。
- 登录涉及密码的请求在前端按开发惯例加密，后端存储使用 bcrypt 哈希。
- 连续登录失败有时间锁定。

### 8.4 其他

- 服务最终由反向代理通过 HTTPS+TLS 暴露到互联网，这部分是我自行配置，应用本身不需要 HTTPS。
- 其他安全相关默认按最佳实践实现。
