### 2.1 `core/security.py`
```python
"""安全工具：RSA、bcrypt、密码规则。"""
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives import serialization, hashes
from passlib.context import CryptContext

_pwd = CryptContext(schemes=["bcrypt"], deprecated="auto", bcrypt__rounds=12)

def generate_rsa_keypair() -> tuple[str, str]:
    """返回 (public_pem, private_pem)，RSA-2048，PKCS8，PEM 文本。"""

def rsa_decrypt(private_pem: str, ciphertext_b64: str) -> str:
    """base64 解码 -> PKCS1v15+SHA256 解密 -> 返回明文。解密失败抛 ValueError。"""

def hash_password(plain: str) -> str: ...
def verify_password(plain: str, hashed: str) -> bool: ...

def validate_password(plain: str) -> list[str]:
    """返回错误信息列表；空列表表示合法。
    规则：长度 8-128；至少含 数字/字母/符号 中两类。
    符号定义：非字母数字的可见 ASCII。"""
```
- 关键：RSA 解密用 `padding.PKCS1v15()` + `hashes.SHA256()`；前端 JSEncrypt 默认 PKCS1v15。
- 密码分类判定：`has_digit = any(c.isdigit())`，`has_alpha = any(c.isalpha())`，`has_symbol = any(not c.isalnum() and c.isprintable() for c in plain)`；`sum([has_digit, has_alpha, has_symbol]) >= 2`。
- bcrypt 警告：passlib bcrypt 对 ≥72 字节密码会截断，本阶段密码最长 128 但实际含两类即可，无需特殊处理。

### 2.4 `core/deps.py`
```python
from fastapi import Depends, Request, Cookie, HTTPException, status
from sqlalchemy.orm import Session

def get_current_user(
    request: Request,
    db: Session = Depends(get_db),
    token: str | None = Cookie(default=None, alias=settings.COOKIE_NAME),
) -> User:
    """从 cookie 读 JWT -> decode -> 查 user。
    无 token: 401 AUTH_REQUIRED。
    user 不存在/status==disabled: 401/403。
    status==deactivated: 允许登录态查看自己信息？决策：deactivated 用户不能登录(登录接口拒绝)，但已签发 token 仍有效直到过期；此处 deactivated 也视为未授权(401 ACCOUNT_DEACTIVATED)。
    返回 User。"""

def require_admin(user: User = Depends(get_current_user)) -> User:
    """role != admin -> 403 ADMIN_REQUIRED。"""
```
- CSRF 依赖：单独写 `verify_csrf(request: Request)`，校验 `request.headers.get("X-CSRF-Token") == request.cookies.get(settings.CSRF_COOKIE_NAME)`。**仅在状态变更接口(POST/PATCH/DELETE)使用**，GET 免。
  - 决策：用依赖 `Depends(verify_csrf)` 显式注入，而非全局中间件（避免 /system/init 在无 cookie 场景卡死 + 简单可控）。
  - `/system/init` 是首个写操作，调用前无 CSRF cookie；决策：**init 接口豁免 CSRF**（首次无 cookie，且无已登录身份可利用），其余写接口均需 CSRF。
  - `/auth/login`、`/auth/register`、`/auth/logout`、`/auth/refresh`：login/register 时用户尚未登录、CSRF cookie 可能不存在。决策：**login/register/refresh 也豁免 CSRF**（这些接口本身有密码/RSA 强保护），**logout 需 CSRF**（防登出 CSRF）。统一：`login/register/refresh/init` 免 CSRF；`logout/me/me/avatar/deactivate` 需 CSRF。

### 2.9 `services/auth_service.py`
```python
def register(db, data: RegisterIn) -> User:
    """1. email 已存在 -> EMAIL_EXISTS 409
       2. 校验邀请码：status==active 且未过期 且 used_by_id is None。
          不合法 -> INVALID_INVITE 400 (统一错误，不泄露具体原因防枚举)
       3. RSA 解密密码 -> validate_password
       4. 创建 User(role=user, status=active)
       5. 邀请码 status=used, used_by_id=user.id
       6. 返回 User"""

def login(db, data: LoginIn, response: Response) -> User:
    """1. 按 email 查 user；不存在 -> INVALID_CREDENTIALS 401（不区分用户存在与否）
       2. status==disabled -> ACCOUNT_DISABLED 403
       3. status==deactivated -> ACCOUNT_DEACTIVATED 403
       4. locked_until > now -> ACCOUNT_LOCKED 403, detail={locked_until, retry_after_seconds}
       5. RSA 解密密码(失败->INVALID_CREDENTIALS 401, 不泄露)
       6. verify_password:
          - 失败: failed_login_count += 1; 若 ==5 -> locked_until=now+15min, failed_login_count 保持5或重置0?决策:到5锁定时计数保持5(解锁后清零); commit; raise ACCOUNT_LOCKED 若刚到5,否则 INVALID_CREDENTIALS
          - 成功: failed_login_count=0, locked_until=None, last_login_at=now; commit
       7. 签 JWT + CSRF token, set_auth_cookies(response,...)
       8. 返回 User
    注意：锁定计数按账号维度(查询后对该 user 行更新)，成功清零。"""

def refresh(db, current_user: User, response: Response) -> User:
    """续签：重新签 JWT 写 cookie，返回 user。"""

def logout(response: Response) -> None: clear_auth_cookies
```
- 锁定细节：`failed_login_count` 到 5 时设 `locked_until = now + 15min`，且此时返回 `ACCOUNT_LOCKED`；锁定期间再尝试登录直接返回 `ACCOUNT_LOCKED`（不增加计数、不重置定时）。锁定自然过期后(locked_until <= now)允许尝试，成功清零、失败继续累计(从当前 count 继续)。

### 2.11 路由 `api/v1/`

`api/v1/__init__.py`：
```python
from fastapi import APIRouter
from app.api.v1 import auth, system, users
router = APIRouter()
router.include_router(system.router, prefix="/system", tags=["system"])
router.include_router(auth.router, prefix="/auth", tags=["auth"])
router.include_router(users.router, tags=["users"])  # /me, /users 前缀各自定义
```

`api/v1/system.py`：
- `GET /initialized` -> InitializedOut（公开）
- `POST /init` -> 依赖：若已初始化则拒(409)；InitIn -> init_system -> 签 JWT+CSRF cookie -> 返回 TokenOut。**免 CSRF**。

`api/v1/auth.py`：
- `GET /rsa-public-key` -> RSAKeyOut（公开）
- `POST /register` -> RegisterIn -> register -> 签 cookie -> TokenOut（免 CSRF）
- `POST /login` -> LoginIn -> login(含 response) -> TokenOut（免 CSRF）
- `POST /logout` -> Depends(get_current_user, verify_csrf) -> logout（需 CSRF）
- `POST /refresh` -> Depends(get_current_user) -> refresh -> TokenOut（免 CSRF，已有 token 即可）

`api/v1/users.py`：
- `GET /me` -> Depends(get_current_user) -> MeOut
- `PATCH /me` -> Depends(get_current_user, verify_csrf) -> MeUpdateIn -> MeOut
- `POST /me/avatar` -> Depends(get_current_user, verify_csrf) -> UploadFile -> AvatarOut
- `POST /me/deactivate` -> Depends(get_current_user, verify_csrf) -> 204
- `POST /me/password` -> Depends(get_current_user, verify_csrf) -> PasswordChangeIn -> 204（**新增**：方案 API 清单写 PATCH /me 改昵称/签名/密码，但密码需验旧密码，拆独立接口更清晰。决策：拆 `POST /me/password`，PATCH /me 只改昵称/签名。）
- `GET /users/{user_id}` -> Depends(get_current_user) -> OtherUserOut
- `GET /users/{user_id}/posts` -> 本阶段返回 501 NotImplemented 占位（动态列表阶段 4 实现），路由先注册避免前端 404。**决策：不注册占位，阶段 4 再加；避免空接口。**（保持清单洁净，本阶段不实现该路由。）
- `GET /avatars/default` -> FileResponse(assets/default_avatar.png)（公开，无依赖）
- `GET /avatars/{user_id}` -> 公开；查 user.avatar_path，无则返回默认头像；FileResponse( STORAGE_ROOT/avatar_path )，防穿越 resolve 校验。

### 2.13 关键决策汇总（后端）
| 议题 | 决策 |
|---|---|
| CSRF 适用范围 | init/login/register/refresh 免；logout/me 写/avatar/deactivate/password 需 |
| 密码改密接口 | 拆 `POST /me/password`，PATCH /me 仅昵称/签名 |
| 头像访问 | 公开，本阶段实现 `/avatars/default` 与 `/avatars/{id}` |
| deactivated 用户登录态 | get_current_user 视为 401 ACCOUNT_DEACTIVATED；登录接口直接拒 |
| 锁定计数 | 到5锁定15分钟，锁定期间不增计数，自然过期后继续累计，成功清零 |
| 错误统一 | AppError + 全局 handler，ErrorOut 格式 `{code,message,detail}` |
| 邀请码错误 | 统一 INVALID_INVITE 不细分（防枚举） |
| avatar_path 存储 | 相对 STORAGE_ROOT，如 `avatars/1_xxx_thumb.webp` |

## 3. 前端详细设计

### 3.1 `api/client.ts`
```ts
// 1. 基础 fetch 封装：credentials:'include'，自动注入 X-CSRF-Token(从 cookie 读)
// 2. 响应：200-299 返回 json；非 2xx 解析 ErrorOut 抛 ApiError(code,message,detail)

```
- CSRF 读取：`utils/csrf.ts` 从 `document.cookie` 读 `moments_csrf`。
- 上传 avatar 用 `FormData`，`client.upload(url, FormData)`。

### 3.2 `utils/rsa.ts`
```ts
import JSEncrypt from "jsencrypt";
export async function encryptPassword(publicKeyPem: string, password: string): Promise<string> {
  const enc = new JSEncrypt();
  enc.setPublicKey(publicKeyPem);
  const out = enc.encrypt(password);
  if (out === false) throw new Error("RSA encrypt failed");
  return out; // base64
}
```

### 3.3 `stores/auth.ts`（Zustand）
```ts

  loading: boolean;       // 初始化时拉取
  initialized: boolean | null;  // null=未查询
  fetchInitialized(): Promise<void>;
  fetchMe(): Promise<void>;

```

### 3.4 `App.tsx` 路由
```
/            -> 重定向：未初始化->/init；未登录->/login；已登录->/settings(本阶段无主页,暂用 settings)
/init        -> InitPage (已初始化则重定向 /login)
/login       -> LoginPage
/register    -> RegisterPage
/settings    -> RequireAuth(SettingsPage)
*            -> NotFound 或回 /
```
- 启动 `useEffect`：先 `fetchInitialized()`，再若已初始化且非 init/login 路径则 `fetchMe()`。
- 动物森友会风格布局：顶部用 animal-island-ui `Title`/`Card` 包裹，背景 `#f8f8f0`（index.css 已设）。

### 3.5 页面（均使用 animal-island-ui 组件）
- `InitPage`：邮箱/昵称/密码/确认密码表单 -> 拉 RSA 公钥 -> 加密 -> POST /system/init -> 成功 setUser + 跳 /settings。
- `LoginPage`：邮箱/密码 -> 拉公钥加密 -> POST /auth/login -> setUser 跳转；含"去注册"链接；错误显示 ACCOUNT_LOCKED 倒计时。
- `RegisterPage`：邮箱/昵称/密码/确认密码/邀请码(从 query `?invite=` 预填) -> 加密 -> POST /auth/register。
- `SettingsPage`：当前用户信息卡片 + 改昵称/签名表单 + 改密码表单(旧密码/新密码/确认) + 头像上传(input file + 预览) + 注销账号按钮(二次确认 Modal)。
- 表单用 animal-island-ui 的 `Form`/`FormItem`/`Input`/`Button`；错误用 Toast/内联提示；Modal 用 animal-island-ui `Modal`。
- **前端不使用 dangerouslySetInnerHTML**，所有用户内容文本节点渲染。

## 6. 注意事项与风险

- **RSA 解密失败**：前端 JSEncrypt 用 PKCS1v15，后端必须用 `padding.PKCS1v15()` 而非 OAEP。
- **bcrypt rounds**：passlib 默认 12，性能可接受；勿设过高。
- **SQLite 并发**：dev 单 worker 无碍；写操作注意 commit。
- **CSRF cookie 首次**：login 成功后 set_auth_cookies 同时写 JWT 和 CSRF cookie；后续请求前端读 CSRF cookie 放头。
- **avatar 防穿越**：`Path(avatar_path).resolve()` 必须在 `STORAGE_ROOT.resolve()` 之内。
- **密码 base64**：JSEncrypt 输出已是 base64 字符串，后端直接 `base64.b64decode`。
- **email 大小写**：注册/登录前 `.lower().strip()` 统一，避免重复注册。
- **passlib CryptContext 弃用告警**：bcrypt 4.x 下 passlib 可能告警，不影响功能，本阶段忽略（或加 `bcrypt__rounds` 抑制）。
