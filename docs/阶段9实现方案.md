## 二、实现方案

### 2.1 T1 + T2：统一响应式布局 `Layout` 组件

**目标**：抽出统一布局，提供顶部导航栏（桌面横向 / 移动端汉堡菜单或自适应换行），内容区居中限宽。把各页面里零散的导航按钮收敛到顶部导航。

**文件**：`src/components/Layout.tsx`

**设计要点**：
1. 顶部导航栏：左侧 Logo/标题「Moments」；右侧导航项。导航项根据 `user` 角色动态显示。
2. 导航项：动态（/feed）、发动态（/post/create）、好友（/friends，带未读请求角标）、设置（/settings）、管理后台（仅 admin）、登出。
3. 响应式断点（CSS media query，无第三方依赖）：
   - ≥ 640px：横向显示所有导航项。
   - < 640px：导航项换行/紧凑显示（保留核心项：动态、发、好友、设置；管理后台与登出可收进一个下拉或保持显示但缩小）。
4. 内容区 `max-width: 680px` 居中，`padding` 随断点调整（桌面 24px / 移动 16px）。
5. 使用 animal-island-ui 的 `Card` 作为导航容器底色，或纯 CSS。Logo 使用 `<Title size="small" color="app-teal">Moments</Title>`。
6. 用 `useAuthStore` 读取 user 角色；登出调用 `logout()` 后 `navigate('/login')`。
7. 好友请求未读数：新建轻量 store 或在 Layout 内 `useEffect` 拉取 `listFriendRequests()` 计数（仅登录后），轮询可选（本期不强制，页面进入时拉一次即可）。导航项「好友」右侧用 animal-island-ui `Tag color="app-red" size="small"` 显示数字（>0 时）。

**改动**：
- 新增 `src/components/Layout.tsx`。
- `src/App.tsx`：把各 `RequireAuth` 包裹的页面统一用 `<Layout>` 包裹（在 RequireAuth 内层）。即：`<RequireAuth><Layout><FeedPage /></Layout></RequireAuth>`。
- 各页面移除页面顶部的零散导航按钮（FeedPage 的刷新/好友/后台/设置/发动态按钮组），保留页面标题与业务内按钮。FeedPage 保留"刷新"按钮（业务操作），移除导航类按钮。

**注意**：InitPage/LoginPage/RegisterPage 不用 Layout（独立全屏页）。

### 2.2 T2 移动端适配打磨（各页面）

**目标**：窄屏（< 640px）下不溢出、不挤压、可点击区域足够。

**改动清单**：
1. `PostCard.tsx`：媒体网格在小屏单图时宽度由 `300px` 改 `minmax(0, 100%)`；操作栏 `gap` 在窄屏收紧；删除按钮在窄屏换行到下一行。
2. `FeedPage.tsx`：顶部工具栏改为 flex-wrap，刷新按钮保留；移除导航按钮（已进 Layout）。
3. `PostCreatePage.tsx`：visibility Radio 在窄屏纵向排列（已是 inline，但容器 `flex-wrap` 确认）。
4. `PostDetailPage.tsx`：评论卡片头像 + 内容在窄屏间距收紧；评论输入区上传按钮文字短化。
5. `AdminPage.tsx`：筛选栏 `flex-wrap`；统计卡片网格在窄屏从 3 列变 1 列（`grid-template-columns: repeat(auto-fill, minmax(140px, 1fr))`）。
6. `UserPage.tsx`：好友操作按钮 `flex-wrap`。
7. 全局：在 `index.css` 增加基础响应式规则与滚动条美化。

**实现方式**：用 CSS `@media (max-width: 639px)` media query 写在组件 inline `style` 不可行（inline 无 media query），因此采用：
- 在 `index.css` 中新增几个工具类（如 `.ai-hide-sm`、`.ai-row-to-col-sm`）配合组件使用；或
- 关键断点处用 JS `useMediaQuery` hook 判断（新增 `src/hooks/useMediaQuery.ts`）。

**推荐**：新增 `src/hooks/useMediaQuery.ts`（`matchMedia` 封装），在需要条件布局的组件中用 hook 切换 style 对象，避免大量 CSS 类。同时 `index.css` 加全局 `@media` 微调（字号、padding）。

### 2.3 T3：全局 Notification 反馈

**目标**：关键操作（发动态成功、删除成功、加好友成功、设置保存成功、邀请码复制成功、admin 操作成功）用 animal-island-ui 的命令式 `Notification`/`notificationOpen` 弹出顶部通知；错误也走通知。

**改动**：
1. 新增 `src/utils/notify.ts`：封装 `notificationOpen` 的便捷函数 `notify.success(msg)` / `notify.error(msg)` / `notify.info(msg)`，统一 position='top'、duration=3（错误 duration=0 手动关闭或 5）。
2. 在以下场景替换内联成功文字为通知（保留错误内联兜底也可，但成功用通知更轻）：
   - `FeedPage`：刷新成功/失败。
   - `PostCreatePage`：发布成功（可保留跳转 + 通知）。
   - `PostCard` / `PostDetailPage`：删除成功、点赞失败。
   - `UserPage` / `FriendsPage`：好友操作成功/失败。
   - `SettingsPage`：保存成功、头像更新、密码修改成功、邀请码复制成功。
   - `AdminPage`：用户操作、删除成功。
3. 注意：`Notification` 需要在组件树挂载其 Provider 吗？查看组件库实现 —— `notificationOpen` 是命令式全局 API（挂载到 body 的 portal），无需 Provider，直接调用即可。在 `main.tsx` 无需改动。

**animal-island-ui Notification API**（已确认）：
```ts
notificationOpen({
  message: "标题",
  description: "描述",     // 可选
  type: "success" | "info" | "warning" | "error",
  position: "top",
  duration: 3,            // 秒；0 不自动关闭
});
```

### 2.4 T4：图片灯箱 `Lightbox` 组件

**目标**：点击 PostCard/详情页/评论图片时，在当前页面全屏遮罩内查看大图（而非 `window.open` 新标签页），支持点击关闭、多图左右切换。

**文件**：`src/components/Lightbox.tsx`

**设计要点**：
1. Props：`{ images: string[]; index: number; onClose: () => void; }`。
2. 全屏 fixed 遮罩 `rgba(0,0,0,0.85)`，居中显示当前图片 `max-width: 90vw; max-height: 90vh; object-fit: contain`。
3. 多图时左右箭头按钮（动物岛风格：圆角、teal/黄色），键盘 ←/→ 切换、Esc 关闭。
4. 视频媒体：若 `kind==='video'`，详情页点击应播放 `<video controls>`（灯箱内判断 url 是否为视频源；当前后端 original_url 对视频是源文件，可直接 `<video>`）。
5. 样式符合 animal-island-ui（圆角、暖色按钮、淡入动画）。
6. **不引入新依赖**，纯 React + CSS。

**改动**：
- 新增 `src/components/Lightbox.tsx`。
- `PostCard.tsx`：媒体网格点击 → 打开 Lightbox（传入当前 post 的所有图片 large_url/original_url 数组 + 点击索引）。视频项点击用 Lightbox 内 `<video>`。
- `PostDetailPage.tsx`：同理，媒体点击打开 Lightbox。
- 评论图片点击：打开 Lightbox（单图）。

### 2.5 T5：XSS 防护复核

**核查结论**：当前所有用户输入内容（动态 content、评论 content、昵称、签名）均通过 React 文本节点 `{post.content}` 渲染，React 默认转义，无 `dangerouslySetInnerHTML` 使用。`whiteSpace: "pre-wrap"` 保留换行，安全。**无需改动**，但需在实现时确保新增组件（如 Lightbox 的 alt）不引入 HTML 注入面。

**确认点**（tool-agent 实现时复核）：
- 全局 grep `dangerouslySetInnerHTML` 应为空。
- `window.open(url)` 中 url 均来自后端拼接的相对路径，无用户可控注入。

### 2.6 T6：好友请求未读角标

**改动**：
- `Layout.tsx`：`useEffect` 登录后调用 `listFriendRequests()`，存未读数到本地 state（或新增 `src/stores/friends.ts` 轻量 store）。导航项「好友」右侧用 `<Tag color="app-red" size="small">{count}</Tag>`（>0 时）。
- 切换到 FriendsPage 后可选择刷新（页面已有自己的拉取）。
- 不做轮询（本期无通知系统，方案明确）。

**新增 store**：`src/stores/friends.ts` —— 存 `unreadCount`、`fetchUnread()`、`clearUnread()`。Layout 挂载时 fetch；FriendsPage 挂载时 fetch 后 clear。

5. **lint/typecheck/build 必须全绿**：实现后运行 `npm run lint`、`npx tsc -b --noEmit`、`npm run build` 验证。

## 六、风险与兜底

- **Layout 包裹可能破坏现有页面样式**：现有页面自带 `maxWidth + margin: auto + padding`，套 Layout 后需确保内容区不双重限宽。方案：Layout 内容区**不设 maxWidth**（各页面自管），Layout 只管顶部导航条。内容区 `padding` 统一由页面管。
- **Notification 全局 API 在 SSR/首次加载时 DOM 未就绪**：本应用纯 CSR，无此问题。
- **Lightbox 键盘事件冲突**：确保 Esc/方向键监听在组件卸载时移除；不与 textarea 输入冲突（仅 Lightbox 打开时绑定，且 stopPropagation 防止冒泡到表单）。
